# Лабораторные работы № 1 и № 2 по дисциплине «Системы обработки больших данных»

Лабораторная работа № 1 — разведочный анализ больших данных с использованием фреймворка `Apache Spark`:
загрузка исходных данных в таблицу `Apache Iceberg`, анализ и очистка датасета.
Лабораторная работа № 2 — машинное обучение на больших данных с использованием `SparkML`
(вариант 2: `RandomForestRegressor` и `LogisticRegression`).

Задания и ноутбуки лежат в каталоге `SOBD/` — клоне репозитория кафедры
[kpdvstu/SOBD](https://github.com/kpdvstu/SOBD).

Ноутбуки выполнены на одноузловом кластере, который повторяет состав учебного кластера кафедры:
`HDFS` и `YARN` из `Hadoop` 3.3.6, `Apache Spark` 3.5.3, `Apache Iceberg` 1.6.0.

## Набор данных

[US Accidents (2016 – 2023)](https://www.kaggle.com/datasets/sobhanmoosavi/us-accidents) —
дорожно-транспортные происшествия в 49 штатах США, собранные из потоков дорожных событий нескольких API.

| Характеристика | Значение |
| --- | --- |
| Объём в формате CSV | 2,8 ГБ (архив 650 МБ) |
| Число записей | 7 728 394 |
| Число признаков | 46 |
| Период | февраль 2016 — март 2023 |
| Главный признак | `Severity` — тяжесть по влиянию на движение, от 1 до 4 |

Перед работой просмотрен список всех 524 ноутбуков вкладки Code на Kaggle; находки самых полезных
(ошибки в погоде, смена методики в 2019 году, различия источников, утечки признаков) учтены в анализе.

## Запуск

Архив с Kaggle распаковать в `SOBD/2024/data/original/` и загрузить CSV в `HDFS`:

```bash
unzip US_Accidents_March23.csv.zip -d SOBD/2024/data/original/
```

```bash
hdfs dfs -mkdir -p /datasets/us_accidents
```

```bash
hdfs dfs -put SOBD/2024/data/original/US_Accidents_March23.csv /datasets/us_accidents/
```

Ноутбуки выполняются по порядку: `lab1/1_Data_loading.ipynb` → `lab1/2_Exploratory_analysis.ipynb`
→ `lab2/1_Random_Forest_Regression.ipynb` → `lab2/2_Logistic_Regression.ipynb`. Таблицы хранятся в базе
`sobd_accidents` каталога `Iceberg` в `HDFS`, модель — в `hdfs:///user/<пользователь>/models/severity-logreg`.

Параметры `Spark` в ноутбуках рассчитаны на кластер с 8 ГБ памяти: два исполнителя по два ядра и 1,5 ГБ,
после перемешивания данные делятся на 16 разделов вместо 200. Полный прогон четырёх ноутбуков занимает
около 40 минут: 3 + 7 минут лабораторная № 1, 17 + 10 минут лабораторная № 2. Ноутбуки запускаются строго
по одному — двум приложениям `Spark` памяти такого кластера не хватит.

## Основные результаты

### Лабораторная работа № 1

* CSV на 2,8 ГБ превратился в таблицу `Iceberg` на ~490 МБ — почти в шесть раз меньше.
* Удалено 117 695 дубликатов (1,5 %) и записи с ошибочной длительностью; осталось 7 538 337 записей.
* Ошибочная погода (−89 и 207 °F, ветер 1087 миль/ч, давление 0) переведена в пропуски; пропуски
  скорости ветра при штиле `Calm` заполнены нулём — тот же штиль в формате `CALM` всегда записан со скоростью 0.
* Осадки и ощущаемая температура до 2019 года почти не записывались (до 90 % пропусков) — удалены.
* Источники размечают тяжесть по-разному, а `Source1` с 2021 года не ставит тяжесть 3 вовсе:
  «падение» доли тяжёлых ДТП с 34 до 3 % — артефакт сбора данных. Тяжесть анализируется внутри `Source2`.
* Главный фактор тяжести — тип дороги: на межштатных магистралях 80 % тяжёлых ДТП, на улицах — 16 %.
  Пики ДТП — 7–8 и 15–17 часов в будни.

### Лабораторная работа № 2

Вариант 2. Обе модели учатся на прошлом и проверяются на более позднем периоде.

* **Регрессия, `RandomForestRegressor`.** Протяжённость затора по условиям ДТП (место, время, тип дороги,
  погода, объекты рядом) на данных `Source1` за 2021 — март 2023: только он измеряет протяжённость,
  а в 2019–2020 годах измерял иначе. Цель — десятичный логарифм протяжённости (значения различаются на пять порядков).
  Кросс-валидация выбрала 40 деревьев глубиной 14. На тесте (июль 2022 — март 2023) $R^2$ = 0,34, типичная
  ошибка — в 2,9 раза; правило «среднее по типу дороги» даёт $R^2$ = 0,24. Главный признак — тип дороги
  (почти 60 % важности): на межштатных магистралях заторы в семь раз длиннее, чем на улицах.
* **Классификация, `LogisticRegression`.** Тяжёлое ли ДТП (тяжесть 3–4) на данных `Source2`, где разметка тяжести
  стабильна. Обучение — 2016–2020, тест — 2021–2022, 126 признаков после one-hot кодирования.
  `AUC-ROC` 0,838 и `AUC-PR` 0,721 на тесте при уровне случайной модели 0,34. С порогом 0,33, выбранным на обучении,
  модель находит 76 % тяжёлых ДТП при точности 62 %. Конвейер с порогом сохраняется в `HDFS`,
  988 тестовых записей — в `streaming-data.csv` для следующей работы.
